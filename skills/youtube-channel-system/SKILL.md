# YouTube Channel System

Turn a creator's goals and capacity into an executable channel system. Support a full channel build or just the requested module.

## Intake and scope

Reuse context already supplied. Establish the minimum needed for the requested module: channel URL or starting point, subject and target viewer, intended outcome, language/market, format (long-form, Shorts, or both), on-camera preference, weekly hours, budget, skills/resources, and relevant performance data. Ask a compact question only where the answer changes the work; otherwise state provisional assumptions and proceed. Do not force a full intake for a title or script request.

For a new channel with no niche, begin with niche selection. For an existing channel with performance concerns, begin with available analytics. For a full system, connect all seven modules, with a practical first-month calendar and prioritized next actions. Do not create 100 ideas or multiple full scripts unless requested or needed for the agreed deliverable.

Read only the reference relevant to the current work:

## Evidence and execution

- Research current competitors, trends, tool capabilities/prices, platform features, and monetization rules when they affect the answer. Prefer official YouTube sources for platform claims, cite URLs and check dates, and label inference. If browsing is unavailable, identify what remains unverified rather than inventing it.
- Use actual channel data when supplied or available through authorized tools. Public views do not establish competitor CTR, retention, revenue, or conversion. Never fabricate analytics, search volume, RPM, or guaranteed growth.
- Make recommendations testable hypotheses. Avoid universal CTR/retention targets, secret algorithm formulas, promised virality, fixed monetization timelines, or unsupported claims of faster production.
- Separate planning from execution: preparing scripts and upload assets does not itself authorize publishing, account changes, purchases, or sponsor outreach. Do those only when the person asks for that specific action.
- Use available media-production skills/tools if the user requests finished media. A thumbnail concept is not a generated image; a production plan is not a rendered video. State what was actually produced.
- When the user must perform a manual step, supply the exact destination URL plus each click and field. Use verified channel-specific deep links when available; do not invent IDs or UI controls.

## Delivery

Lead with the recommendation or completed artifact, then the evidence and practical next steps. Scale the output to the request. Use tables for calendars, ranked ideas, and experiments when useful. Explicitly separate observed facts, assumptions, and estimates. End substantial plans with the immediate next actions, their owner, effort, and success measure. Persist briefs or logs only where useful and within the user's chosen workspace; do not silently create recurring automations.
