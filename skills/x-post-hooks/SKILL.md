# X post hooks

A hook is the first line of a post, written to stop the scroll. Use one on many posts, not all of them. A feed of nothing but hooks reads as bait, and plain statements are part of a believable voice.

## Workflow

1. **Pick the posts.** In a batch, decide how many get a hook, and leave the rest plain. For a single post, use a hook when the facts support a strong opening, and write a plain statement when they do not.
2. **Find the strongest true claim.** Start from the post's facts and ask what would make the intended reader stop. Do not start from a template, or the post ends up saying something the facts do not support.
3. **Pick a type from the table.** Check its "Needs" column. If the post cannot supply that, pick another type or go plain.
4. **Vary it.** Do not use the same type twice in a day, and vary against the account's recent posts, so no opening starts to feel repeated.
5. **Fill it with real subjects.** Use the account's own field and the things it really works on. A hook that could fit any account fails.
6. **Pay it off in the same post.** A short post fits the hook and the payoff in 280 characters. A long post puts the hook and the point in the first 280 characters, because X hides the rest behind "Show more".
7. **Check it.** Reject the hook if any answer is no. Is it true? Does the post deliver what the hook promises? Would the author say it out loud to a peer?

## Hook types

| Type | Shape | Needs |
| --- | --- | --- |
| Role call | Name the reader's role in the opening | A point only that role cares about |
| Two camps | Split people into two kinds | A real difference in what they do |
| Over, use this | One approach has stopped working, and here is its replacement | A real shift and a named replacement |
| Wrong belief | A common belief about a topic does not hold | The belief stated exactly, and the evidence |
| Overlooked | A detail few people have noticed | A specific fact from the source |
| Working method | Our exact setup or process, free to copy | The real steps, listed in the post |
| Read first | A warning before a specific task | A specific risk in that task |
| Numbered lessons | N lessons from shipping or building something | All N listed, from real work (long posts) |
| Mistakes | N mistakes to stop making | Mistakes you made or a source documents (long posts) |
| One checklist | One complete checklist for a job | A complete list (long posts) |
| Result in time | A measured result in a stated time | Real numbers |
| Reversal | We were wrong about something | A real change of mind, and what changed it |

## Use only when it really happened

- **First-time share:** only when something new and public really exists.
- **Near-quit story:** only when the author has said so. Never invent one.

## Never use

- Made-up percentages, or "most people" numbers with no source.
- Claims about revenue, earnings, clients or prices that the author has not made in public.

## Voice rules

No hype words, no rhetorical question as an opener, no "here's why" teaser, no thread bait. State only facts seen in a source. When a post comes from someone else's story, write your own hook and never reuse theirs.

## Shapes that fit

These show the tone. Never reuse them word for word.

- Role call: "If you run a small bakery, you probably don't need a loyalty app."
- Two camps: "There are two kinds of bakeries: ones that sell out by noon and ones that bake too much."
- Over, use this: "Punch cards are the wrong default for a small shop. Learn your regulars' names."
- Read first: "Read this before you add delivery to a one-oven bakery."
